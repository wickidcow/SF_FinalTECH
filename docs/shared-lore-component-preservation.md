# Shared lore edits: preserve native components and legacy method contracts

The shared ItemStackUtil lore-edit methods previously converted the complete existing lore to legacy strings and parsed it again even when only one line changed. Rich component data in unrelated lines could be lost, and all of those lines incurred unnecessary serialization work.

Thirteen existing public descriptors are retained. Prepend, append, last-line replacement/removal and offset replacement now delegate to a package-private component helper. Existing prefix/suffix components are retained as immutable values, only newly supplied String lines are decoded, and the String-returning last-line getter serializes just that line. Null/empty lore, padding beyond the old size, empty replacements, first/last positions, explicit full replacement for negative offsets, and repeated non-deduplicating append behavior are preserved.

The change is limited to lore access/delegation. It does not edit the utility's item serialization/deserialization, typed persistent data, comparison or stack-transfer methods, nor item/research IDs, recipes, machine storage, energy, ticker behavior, migration defaults, language recovery or resource-pack mappings. The existing legacy String getters/setters used elsewhere remain in place; no historical persistence bridge is removed. No dependency or warning-suppression changes are introduced.
