# SF_FinalTECH v3.0.17 — lock/shutdown safety and exact comparator boundaries

New immutable raw-JAR release containing maintained FinalTECH production fixes merged since [v3.0.16](https://github.com/wickidcow/SF_FinalTECH/releases/tag/v3.0.16). This release does not migrate or rewrite saved item data, menu inventories, cargo, storage identifiers, recipes, owner configuration or typed PDC.

## Changes since v3.0.16

- **Shutdown concurrency:** queued `ServerRunnableLockFactory` callbacks return a terminal, cancelled `FutureTask` when shutdown begins, including callbacks that have not acquired their object locks. Existing queued holders are not released or overwritten by a rejected task. Lock waiting no longer recursively recovers while the server is stopping, and the aggregate wait is bounded to avoid indefinite shutdown hangs.
- **Exact lookup correctness:** `CompareUtil.getIndex` and `getIntIndex` use inclusive binary-search boundaries and signed-safe `Integer.compare` rather than subtracting potentially overflowing extremes. The methods continue to return `-1` when an item does not match. No stored item quantities or IDs are changed.
- **Build reproducibility:** preserve the exact canonical FinalTECH project manifest, the plugin descriptor and relocated bStats classes without leaking duplicate shaded signatures. The raw artifact is checked against Java 21 bytecode and actual source version.
- Keep the current Slimefun Legacy / Paper 1.21.11 compatibility baseline; source CI also compiles against Paper 26.2 and an explicitly selected stable Paper 26.3 API, and runs the existing storage/identity/concurrency and scheduler safety scripts.

## Preservation and testing

An exact-source green CI build with reviewed release checks is **not proof** that historical AlbionMC inventories, network Cargo, Matrix Reactor and Folia multi-region gameplay have been verified end-to-end. Those remain staging acceptance tasks. The separate Folia test may apply a temporary descriptor to a disposable diagnostic JAR; the distributed production plugin descriptor remains unchanged.

Publication requires an exact current `main` SHA, green source/test pipeline, canonical `SF_FinalTECH3.0.17.jar` from that exact run, and a valid official SHA-256. The publisher must refuse existing tags and assets and verify the official release download byte-for-byte. Earlier v3.0.16 remains immutable.
