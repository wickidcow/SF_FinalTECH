# FinalTECH 3.0.16

FinalTECH keeps its existing Java 21 output and Paper/Purpur runtime baseline.
Existing item and research IDs, recipe contents, machine identities, storage keys,
amounts and configuration migration versions are preserved.

## Changes

- Preserve Bukkit tick scheduling on Paper/Purpur while routing the startup timer
  and delayed registry setup through the appropriate native Folia schedulers.
- Schedule delayed item and multiblock recipe registration with the original addon
  owner and cancel the tracked startup tasks during plugin shutdown.
- Make the experimental Folia diagnostic fail on plugin enable errors, wrapped
  scheduler exceptions, incomplete Doctor reports and unclean restart storage.
- Publish versioned JARs without moving an existing release tag or replacing an
  existing artifact. Pull requests and manual validation runs cannot publish.

## Experimental Folia validation

The readiness workflow tests a disposable JAR copy on Folia 26.3. Only that copy
receives a Folia descriptor declaration; the production plugin descriptor remains
unchanged. The test covers startup, delayed setup, Doctor diagnostics, shutdown and
a second boot. It does not certify every machine, menu, cargo topology, cross-region
transfer or populated historical world on Folia.
